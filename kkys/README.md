# qflarebot-plugin-kkys

[QFlareBot](https://github.com/QFlareBot/QFlareBot) 插件：搜索 kkys01.com（可可影视）影片、解析 m3u8/mp4 播放直链、
生成一起看房间链接。移植自 `kkys-nixiang` 仓库的 `kkys_py/kkys_cli.py`，业务行为与那个 CLI 对齐。

## 命令

| 命令 | 说明 |
| --- | --- |
| `/看剧 <片名>` | 搜索并列出结果，点按钮选片 → 选线路 → 选集（别名 `/kkys`、`/可可影视`） |
| `/看剧 <片名> <集数>` | 一步到位：搜索 → 最佳线路 → 指定集 → 直链 + 一起看链接 |
| `/一起看 <视频直链>` | 把直链转成一起看房间链接 |
| `/看剧 状态` | 反爬体检：现解一次凭证 + 真打一次搜索，报出解算耗时（仅管理员） |
| `/看剧 刷新` | 用真实搜索验证反爬链路是否通（仅管理员） |

> **⚠ 需要 Workers 付费版。** 站点反爬的凭证是一次性的，插件每次操作都得现解一次 PoW
> （7–50 ms CPU），而免费版单次只有 10 ms。免费版上会表现为「时好时坏、经常搜索失败」。
> 用 `/看剧 状态` 看「解算耗时」就能确认。详见下面「反爬」一节。

集数写在片名后面，用空白分隔：`/看剧 斗罗大陆 120`。片名本身带数字（`/看剧 斗罗大陆2`）不会被当成集数——
不带空白分隔的数字仍是片名的一部分，走搜索列表。末尾数字搜不到结果时也会退回按整串当片名再搜一次。

播放结果带一排按键：**最新一集**（当前线路最后一集）、**换线路**（回到线路列表，读会话不发请求）、
**一起看**（用会话里缓存的直链生成房间链接，不再请求站点）。会话存 KV，30 分钟过期。

选线路进到剧集页后，底部也有一个**换线路**（只在有多条线路时出现）；单线路的片子不加这个按钮，
因为点进去还是同一条线路，纯噪音。

## 额度与子请求

免费版 Worker 一次事件只有 **50 个子请求**、**10 ms CPU**，全机器人所有插件共用，所以这里做了几处收敛：

- **凭证在同一次事件内复用**。`/看剧 斗罗大陆 2` 要依次走搜索、详情、播放页，每步都要凭证；
  按客户端实例缓存一个 Promise，同一事件内只解一次 PoW（跨事件不复用，见「反爬」一节）。
- **挑战页不重复请求**。第一次首页请求返回的 850 响应里就带着挑战页，直接交给 PoW 解算，
  不再自己再拉一遍首页。
- **换线路 / 一起看都是零请求**。线路和剧集在选片时已经全存进 KV，这两个按键只读会话。
- **循环里不重解凭证**。试多条线路时 `attempts=1`，失败直接换线路，避免 5×2×19 ms 的 CPU 峰值。

即便如此，一次操作的最小 CPU 成本仍是**一次 PoW 解算（7–50 ms）**，超过免费版的 10 ms。
所以这个插件需要 Workers 付费版，详见「反爬 · CPU 预算」。

## 配置

面板「插件 → 可可影视」里改：

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 过滤无关搜索结果 | 开 | 站点是模糊匹配，搜不到时会返回无关影片；开启后按标题相似度剔除（判定宽松，避免误杀） |
| 搜索结果展示条数 | 8 | `/看剧 <片名>` 最多列几条 |
| 一起看地址 | `https://yqk.060908.xyz/watch.html` | 换成自己部署的一起看站点 |
| 手动 Cookie | 空 | **应急**：站点改了挑战页格式、自动破解失效时，从浏览器复制 `cdndefend_js_cookie=...` 填进来 |

## 反爬（cdndefend）

站点直连首页返回 **HTTP 850** + JS 挑战页，破解逻辑与 CLI 一致：解析混淆数组 → 模拟数组旋转 → 取 40 位 hex 的 `c`
与检查偏移 `n1` → 穷举 `i` 使 `SHA1(c + i)` 的 `[n1] == 0xB0 && [n1+1] == 0x0B`。

### 凭证是一次性的（这里踩过大坑）

**解出来的 cookie 只能用极短时间。** 实测：

```
解出 cookie → 立刻请求首页 → 200 ✓
等 5 秒 → 用同一个 cookie 请求首页 → 850 ✗
```

而且挑战值 `c` 也会轮换（同一出口 IP 连续请求，`c` 会从 A 变成 B）。

所以「解一次、存 KV、12 小时内复用」这条路**必然失败**，症状就是：
`/看剧 刷新` 报「凭证已刷新」（因为它刚解出来、第一次用成功了），
之后的 `/看剧 仙逆` 全部 850，`/看剧 状态` 又报「Cookie 无效」。

现在的做法：

- **不跨事件复用凭证**。KV 里只保留 5 秒内的（同一次事件内 `search → detail → play` 三步连续用，
  实测全部 200），超过窗口一律重新解。
- **每次失败都换新凭证重试**。默认 2 次（一次解算 7–50 ms，多试几次就把 CPU 预算烧光了）。
- **循环里不重试**。`/看剧 <片名> <集数>` 最多试 5 条线路，每条都重解就是 5×2×19 ms ≈ 190 ms 纯 CPU，
  所以循环内传 `attempts=1`，失败直接换下一条线路。

### CPU 预算：免费版扛不住

PoW 实测 **7–50 ms**（中位 19 ms，取决于 `n1` 和命中位置），而 **Worker 免费版单次 CPU 上限是 10 ms**。

| 方案 | 单次操作 CPU | 免费版 |
| --- | --- | --- |
| 旧实现（存 KV 复用） | 第一次 20 ms，之后 ≈ 0 | 能用，但第二次请求起必然 850（凭证已失效） |
| 新实现（每次现解） | 19–40 ms | **会超，请求被平台掐断** |
| 付费版（30 s CPU） | 19–40 ms | 没问题 |

**所以这个插件实质上需要 Workers 付费版。** 免费版会表现为「时好时坏、经常报搜索失败」——
那不是逻辑 bug，是 CPU 被掐。`/看剧 状态` 会打印「解算耗时」，超过 10 ms 就说明在免费版上。

### 站点对 XHR 的处理

实测（2026-11-21，Chrome 真实浏览器）：同一个搜索 URL、同一个 cookie，

- **直接导航**（地址栏打开 / 点链接，`Sec-Fetch-Mode: navigate`）→ **200**
- **`fetch`**（XHR，`Sec-Fetch-Mode: cors`）→ **850**

也就是说站点把「页面导航」和「接口调用」分开对待。Workers 里的 `fetch` 一定是 XHR 类型，
没法伪装成导航（`Sec-Fetch-*` 是浏览器加的，服务端能识别）。这也是为什么这个插件在
Cloudflare 上比在本地 Node 上更容易被拦。

### 站点改版时的信号

站点改混淆格式时正则会失配，日志里会出现「反爬挑战页格式变了（正则失配）」——这时要重新分析挑战页 JS。
面板里的「手动 Cookie」**不是**可靠的应急手段（一次性凭证，从浏览器复制的那条通常已经失效），
但它填错也不会卡死：拦截时会自动退回自动破解。

## 与 CLI 的其它差异

- **页面解析全是正则**，没有 BeautifulSoup。正则对着真实页面写，样本固化在 `src/__fixtures__/`（真实页面截取），
  改解析逻辑时对着样本改，`src/kkys.test.ts` 会立刻告诉你有没有解析错。
- **线路↔剧集仍然按 `.source-item-num` 累计切片**还原（详情页把 25 条线路的剧集拼在一个扁平 `.episode-list` 里，
  一条线路会被多个 `source-item` 复用，按位置对齐必然错位）。会话里存的是扁平剧集串
  `lineId-epId\t名称`，播放页 URL 由 `vodId-lineId-epId` 拼回来。
- **t 参数过期**的判定沿用 CLI 的思路：搜索返回空列表时强制重取一次 t 再搜一遍（站点此时返回 200 + 空列表，
  光看状态码分不出来）。
- **凭证管理与 CLI 不同**：CLI 端跑在独立进程里、可以长期持有 cookie；Worker 里不行，见上面「凭证是一次性的」。

## 开发

本插件是 [QFlareBot-Private-Plugin](https://github.com/Rain48698/QFlareBot-Private-Plugin) 仓库里的 `kkys/` 子目录。
SDK 与构建工具不发 npm，从 QFlareBot 源码构建——插件在仓库里深一层，所以 **QFlareBot 检出要放在仓库的上一级**：

```
D:\code\
├── QFlareBot\                        ← 框架源码检出
└── QFlareBot-Private-Plugin\
    └── kkys\                         ← 本插件
```

```bash
cd D:/code/QFlareBot-Private-Plugin/kkys
rm -rf node_modules dist && rm -f package-lock.json   # 挪过目录就必须重生 lockfile
npm install
npm run typecheck
npm test          # @qqbot/sdk/testing 直接驱动处理器，不需要机器人
npm run build     # 生成 dist/plugin.js 与 dist/manifest.json
npm run sync      # 构建并把 dist/manifest.json 复制到插件目录（声明清单，随代码提交）
node ../scripts/check-manifest.mjs .
```

`devDependencies` 里的 `file:../../QFlareBot/packages/*` 就是那份检出（退两级），**别改成别的层级**；
仓库根的 `.github/workflows/ci.yml` 按 matrix 对每个子目录跑同一套检查，CI 里的检出布局与本地一致。

`manifest.json` 是**声明清单**：机器人安装前读它展示权限、检查撞名与依赖，构建时再与源码抽出的清单比对，
不一致就失败。改了插件定义就跑 `npm run sync`，CI 会检查它有没有过期。

## 装到机器人

面板「插件 → 安装插件」粘贴（`#` 后面是子目录）：

```
git:Rain48698/QFlareBot-Private-Plugin@ed2ab41e368d474ae7493a0c610b66390b337cc2#kkys
```

仓库根的 [README](../README.md) 里有这条链接的最新版本——改代码推上去之后跑
`node scripts/update-readme-links.mjs` 会把两处都更新。**要用完整 40 位 sha**：短 sha 和 GitHub 链接都要调一次
GitHub API，面板的匿名配额只有每 IP 每小时 60 次，超了会报一个很像「仓库不存在」的 403。

安装记录钉在那个 commit 上，推新代码不会自动生效；更新走面板「已装插件 → 检查全部更新」。
本插件没有第三方运行时依赖、没有 Durable Object，装之前不需要往机器人仓库补 `migrations`。

## 测试

单元测试不需要机器人和网络：

| 文件 | 测什么 |
| --- | --- |
| `src/kkys.test.ts` | 纯函数：页面解析（对 `src/__fixtures__/` 的真实页面）、PoW 解算（用 `node:crypto` 的 SHA-1 反向校验）、标题相关性、线路切片、链接工具 |
| `src/index.test.ts` | 命令与按键的端到端：桩 `fetch` 走完首页 → 搜索 → 详情 → 播放页，断言回复内容、反爬自动破解、会话复用、按键数据链路、按键 label 的显示宽度 |

改解析正则时对着 `src/__fixtures__/` 里的样本改，`kkys.test.ts` 会立刻告诉你有没有解析错。

改按键时注意这两条兜底，它们挡的是「不报错但功能坏了」的问题：

- **按键 data 的前缀必须是插件真有的处理器名**。`button.callback(..., { id: 'lines' })` 里 id 写错时，
  构建期不拦、运行期不报错——运行时找不到处理器就静默跳过、照样回 0，表现是「点了没反应」。
- **按键 label 按显示宽度算，不是字符数**。QQ 侧汉字算 2、英文数字算 1，`FF线路·播放快/高清`
  只有 11 个字符却有 16 宽度。按 `length` 截断会看着没超、实际被平台截在半个词上
  （`中国大陆加速` → `中国大陆加`）。插件里用 `truncateLabel()` 按宽度截，测试也按宽度断言。

### 真机验证（要联网）

单元测试用的是固定样本，站点改版时样本不会自己变。想确认「现在这一刻」还能不能用，跑真机脚本：

```bash
cd D:/code/QFlareBot-Private-Plugin
node scripts/live/build.mjs kkys          # 打包成 Node 能 import 的 ESM（产物在 .cache/）
node scripts/live/kkys-chain.mjs          # 链路：首页 → 反爬 PoW → 搜索 → 详情 → 播放页 → 直链可播
node scripts/live/kkys-buttons.mjs        # 按钮：选片 → 线路 → 剧集 → 直链 → 一起看 → 最新一集
```

`kkys-chain.mjs` 会真的去拉 m3u8 检查是不是有效播放列表，`kkys-buttons.mjs` 会把真实数据喂给
插件的 `commands` / `buttons` 处理器，并断言每个按键的 data 指向真有的处理器、label 不超宽。
两个脚本都靠真实网络，跑得慢、会受站点状态影响，所以不入 CI。

站点真改版时，脚本会把失配处的 HTML 片段打出来，直接看是哪条正则不匹配了。
